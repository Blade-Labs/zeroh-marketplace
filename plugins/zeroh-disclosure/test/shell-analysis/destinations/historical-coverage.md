# Historical destination and protection seeds

The generic FINDINGS1–9 labels inherited from WIP are not a completeness proof.
`historical-seeds.json` identifies destination and protection variants by their
original finding item; each row uses fake data and authored expected effects.
Supplemental rows are analysis-only until their client/protection effects have
independent execution proof. The release gate must not certify those effects
from analyzer output.

Original FINDINGS1 is scratchpad/astra-review/FINDINGS.md; FINDINGS2–9 are the
corresponding numbered files. FINDINGS6 and FINDINGS7 concern detector behavior,
not mysql or tar destination provenance: their generic WIP labels must not be
read as exact reproduction coverage. Detection, proxy-isolation, receipts and
watcher findings belong to phases 47, 52 and 54 under the accepted phase 42
record. This phase does not change their implementations.

The existing spike appendix covers attached Python/Node writes, ordinary AWK
output, basic Git custom transport/push, ripgrep preprocessing, sort execution
options and less commands. Supplemental seeds add missing spelling/context
variants, including actual IP_ADDRESS typing, literal restored references,
PowerShell stop parsing, local-read false-stop controls and protected writes.

Outstanding independent semantics: pinned wildcard DNS upstream extraction,
real resolvectl/systemd-resolved search domains, source/dot scripts, custom Git
transports/extension execution, and archive member/protected-write effects.
The shell argv printer proves expansion only. These gaps must stay explicit
until execution fixtures demonstrate their effects.
