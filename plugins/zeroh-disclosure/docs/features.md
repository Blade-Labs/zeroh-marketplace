# Features

Every user-visible feature of ZeroH Disclosure 1.0.0-rc.2, with its status on each platform the
plugin targets. Use it to track parity as ZeroH comes to Codex and OpenCode.

[features.json](features.json) holds the same list for tools: feature ID → platform →
`{status, note}`. It is the source; the table below is generated from it
(`node scripts/features.mjs --write`), a test keeps the two in sync, and every feature names the
code or test that implements it. The release pipeline refuses a release whose list is out of date,
and each CHANGELOG section lists the feature IDs it adds or changes on a `Features:` line.

**Statuses.** `shipped`: in this release. For a platform ZeroH does not ship on yet: `planned`
means the host allows it (the note says how); `partial` means the host allows only part of it (the
note says what is missing); `not possible` gives the reason; `unknown` means not researched or not
verified yet. The Codex (CLI 0.156) and OpenCode (opencode-ai 1.18.32) statuses come from research
on 2026-09-25: the host documentation and source, and live runs where the note says so.
