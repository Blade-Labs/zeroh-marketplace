# Optional delivery setup

A local prototype does not need CI or deployment. When delivery is explicitly in scope, inspect existing workflows and adapt the provider's current official guidance to the project's real install, test and build commands. Preserve existing jobs and secrets handling; resolve collisions in the approved diff.

Use normal framework selection and host resource admission where available. Do not install a custom shard planner, Roadmap manifest adapter or seven-slot gate configuration. Verify any workflow edits with available provider tooling and report unexecuted remote behavior. Setup approval is not permission to publish or deploy.

Existing generated workflows and scripts remain consumer-owned. Do not remove or rewrite them during a plugin update.
