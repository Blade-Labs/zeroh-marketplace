# Inspect actual project facts

Look for implemented entry points, source boundaries, package/build manifests, meaningful tests and documented run commands. Read existing product and architecture guidance. Marker files are clues, not proof of a working foundation: an empty package manifest or README may belong to a new project.

Classify only useful findings: missing, partial, stale or already adequate. Cite the actual path or failed command. Offer a focused improvement; no fixed marker count or required document inventory.
