# Intent-to-green-PR visual guide layout

Status: ratified 2026-09-04. Evolve `docs/orientation.html`; do not create a second product surface.

## Canon

Use Zeroh Disclosure: IBM Plex Mono headings, IBM Plex Sans body, and its semantic
off-white/electric-teal tokens and assets. This is an engineer-facing explanation, not a marketing
microsite. Facts come from generated projections; prose is concise, factual, and neutral.

## Information order

1. Outcome, audience, supported hosts, and user-authorized actions.
2. Five-minute Claude and Codex routes.
3. Intent → design → phases → review → validation/correction → PR → CI → evaluation.
4. Persistent artifacts, owners, worktrees, and receipts.
5. Halt and recovery matrix.
6. Versioned capability matrix.
7. Superpowers comparison labelled observed fact, measured result, or interpretation.
8. Troubleshooting and documentation map.

README carries the first-screen summary and a static lifecycle visual. GitHub Markdown is complete
independently. HTML is the richer generated rendering suitable for GitHub Pages. There is no
bundled ELI5 skill and no ELI5 invocation copy.

## Accessibility

Every diagram has ordered-text equivalence. Use semantic landmarks, heading order, table captions,
keyboard navigation, persistent focus, icon+label status, AA contrast, 320px reflow, reduced
motion, labelled external links, and font fallbacks that never hide content.
