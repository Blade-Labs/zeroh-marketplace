# Roadmap skill authoring

Skills should help a native session make the next useful decision. Keep descriptions specific, instructions concise and paths/commands truthful. Read the current consumer schema instead of duplicating it as a second contract. Put optional guidance behind references only when it earns its cost.

Do not add mandatory report fields, fixed panels, repeated owner approvals or a new script because a process can be described deterministically. Retained code has bounded responsibilities: scaffold, ownership, factual progress and consistency validation. Any new runtime responsibility needs explicit scope and inventory review.

Describe the actual host capabilities without hardcoded model aliases or guessed tool signatures. Preserve independent judgment and original intent; do not replace either with scoring or a self-review role-play. User authorization persists and takes precedence over a skill's default routine.

Check changed skill references and commands against the shipped package. Regression checks should exercise real surviving behavior, not snapshot entire instruction text. Validate native behavior with a bounded actual run before making host-support or performance claims. Historical Gauntlet records remain evidence, not an instruction to restore retired machinery.
