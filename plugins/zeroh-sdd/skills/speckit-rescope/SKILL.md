## User Input

```text
$ARGUMENTS
```

You **MUST** consider the user input before proceeding (if not empty). The input describes the scope change.

## Outline

### Step 1: Identify Current Artifacts

Read the active spec directory and catalog what exists:

| Artifact | Exists? | Last Modified |
|----------|---------|---------------|
| spec.md | | |
| research.md | | |
| plan.md | | |
| data-model.md | | |
| tasks.md | | |
| shape-briefs/*.brief.md | | |
| checklists/*.md | | |
| verify.md | | |

### Step 2: Impact Assessment

For each artifact, determine if the scope change **invalidates** it:

| Artifact | Status | Reason |
|----------|--------|--------|
| research.md | PRESERVE | Research findings are almost always still valid |
| spec.md | INVALIDATE / PARTIAL | If scope changes WHAT we build |
| plan.md | INVALIDATE / PARTIAL | If scope changes HOW we build |
| data-model.md | INVALIDATE / PARTIAL | If entities change |
| tasks.md | INVALIDATE | If plan changes, tasks must regenerate |
| shape-briefs/ | PRESERVE / INVALIDATE | Only if affected entities changed |

**Rules:**
- **Research is ALWAYS preserved** (100% of the time — LM-7 proven invariant)
- **Spec** is invalidated only if the scope change contradicts existing user stories
- **Plan** is invalidated if architecture decisions change
- **Tasks** are invalidated if the plan changes (tasks derive from plan)
- **Shape briefs** are invalidated only for affected entities

### Step 3: HITL Gate (MANDATORY)

Present the impact assessment to the user:

```
## Rescope Impact Assessment

Scope change: {description}

### Will PRESERVE (no changes):
- research.md — findings still valid
- {other preserved artifacts}

### Will UPDATE (partial changes):
- spec.md — {what changes and why}
- {other updated artifacts}

### Will REGENERATE (from scratch):
- tasks.md — depends on updated plan
- {other regenerated artifacts}

**Proceed with rescope?** (yes/no)
```

**Do NOT modify any artifact without explicit user approval.**

### Step 4: Execute Rescope

After user approval, update ONLY the invalidated artifacts:

1. **Update spec.md** — modify affected user stories, preserve unaffected ones
2. **Update plan.md** — modify affected architecture decisions
3. **Update data-model.md** — modify affected entities
4. **Delete tasks.md** — will be regenerated by `/speckit-tasks`
5. **Update shape briefs** — modify affected briefs, preserve unaffected ones
6. **Commit**: `"refactor(spec): rescope — {what changed}"`

### Step 5: Re-Enter Pipeline

After rescope, re-enter the pipeline at the earliest invalidated phase:

- If spec changed → re-run from `/speckit-plan`
- If plan changed → re-run from `/speckit-shapes`
- If only tasks changed → re-run from `/speckit-tasks`

Report: "Rescope complete. Re-enter pipeline at `/speckit-{phase}`"

## Key Principles

1. **Rescope is surgical**, not a restart. Preserve everything that's still valid.
2. **Research is never thrown away.** It cost tokens to produce and its findings don't expire with scope changes.
3. **HITL gate is mandatory.** The user approves the impact assessment before any modifications.
4. **Re-entry is automatic.** After rescope, tell the user where to re-enter the pipeline.
