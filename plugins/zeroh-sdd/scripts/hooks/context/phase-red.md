You are in the **RED** phase. The goal is to write FAILING tests that define what "correct" means.

**Allowed:** Writing test files, test scaffolds from acceptance criteria, shape files
**Not allowed:** Implementation code that makes tests pass

Tests MUST fail. If they pass immediately, they are not testing new behavior — they are documenting existing behavior (test capitulation).

**Red flags:**
- "This test is too hard, I'll write a simpler one" → NO. The acceptance criteria define what to test.
- "29/30 is close enough" → NO. Fix the failing test, don't skip it.
- "I'll add proper tests later" → NO. Later never comes.
